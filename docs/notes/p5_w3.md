## Decisions I made

- 2026-11-05 · R38 · s1423 comes from the TTU mirror (`www.pld.ttu.ee/~maksim/benchmarks/iscas89/bench/`), the first public mirror that answered; URL, date and sha256 in `data/README_s1423.md`. The fallback `tools/gen_netlist.py` was not needed. Source: PROMPT_P5.md W3 R38. Later: none.
- 2026-11-05 · R38 · s1423 converts to 748 instances, not ~1000: the brief's "~1000 instances" is read as an order of magnitude; the converted design is the benchmark itself, so no padding was added. Source: PROMPT_P5.md §2 R38. Later: none.
- 2026-11-05 · R38 · Instance names drop a leading `G` before a digit (`G14` -> `U14`, `G5` -> `FF5`), which is what `data/s27.v` does; other net names are used as they are (`G701BF` -> `U701BF`, `q` -> `FFq`). Intermediates are nets `<net>_t<i>` driven by `U<net>_t<i>` (same `G` rule), `i` from 0 in creation order. Because the names then equal `data/s27.v`'s, the s27 test compares all three files at `--tol 0`, not only `endpoints.tsv`. Source: PROMPT_P5.md R38. Later: none.
- 2026-11-05 · R38 · Balanced tree for n > 2 inputs: the input list is split recursively into a first half of ceil(n/2) and the rest; the root is `NAND2`/`NOR2` for the inverting kinds, `AND2`/`OR2` otherwise. 1-input AND/OR become `BUF`, 1-input NAND/NOR `INV`; XOR/XNOR with other than 2 inputs, and any other gate kind, are errors. A PO that is directly a PI is an error (it would need an `assign`, which the subset does not have). The net name `clk` is reserved. Source: PROMPT_P5.md R38. Later: none.
- 2026-11-05 · R38 · "Add s1423 to the golden-format CLI test" is done in `tests/test_bench2v.py` (`S1423Tests`), not in `tests/test_cli.py`, which W3 does not own. Source: PROMPT_P5.md §3 (ownership). Later: the lead may move it into `test_cli.py`.
- 2026-11-05 · R38 · s1423 SDC: input delay 0.5 and output delay 0.5 (plain, both facets) on every PI / PO, period 75.6 from a first run at 100 (numbers in `data/README_s1423.md`). Source: PROMPT_P5.md R38. Later: none.
- 2026-11-05 · R39 · Route: Docker is unavailable (lead), so route 2. Homebrew on this Intel Mac (macOS 15.7, x86_64) is a Tier 3 configuration with no bottles for `cmake`, `tcl-tk`, `swig`, `zlib`; `cmake`, `swig` and `tcl-tk@8` (the version OpenSTA's Brewfile names) were built with `brew install --build-from-source`, `bison` / `flex` / `eigen` came as bottles, zlib is the macOS SDK's, CUDD 3.0.0 was built from `github.com/cuddorg/cudd` into `~/tools/cudd`. Source: PROMPT_P5.md R39 route 2. Later: none.
- 2026-11-05 · R39 · OpenSTA source: `github.com/The-OpenROAD-Project/OpenSTA` (the OpenROAD fork the brief points to; its README names `parallaxsw/OpenSTA` as upstream), shallow clone of the default branch into `~/tools/opensta`; the commit is in `ref/README.md`. Source: PROMPT_P5.md R39. Later: none.
- 2026-11-05 · R39 · Dump route: per-pin values through `get_property` (`arrival_*`, `slack_*`, `slew_*`, which this OpenSTA has; ports through their top-level pin, `sta::find_pin`), paths through `find_timing_paths` + `get_property $end points` + `$point edge`, because the JSON report (`report_checks -format json`) has no rise/fall per point and `paths.txt` needs one. The `report_checks -format full_clock_expanded` text is still written, for people. Source: PROMPT_P5.md R39 ("through get_property if the properties exist"). Later: none.
- 2026-11-05 · R39 · `to_golden.py` endpoints are the endpoints OpenSTA reports a path end for; `rf*` per check uses the same tie rule as the toy (smaller slack, ties to `r`), from the pin slacks. `--toy-pins` is optional: only with it does the adapter add all-NA rows for the other tool's pins and write `missing.txt`, so the adapter alone stays a pure rewrite of OpenSTA's numbers. Source: PROMPT_P5.md R39. Later: none.
- 2026-11-05 · R39 · `tests/test_ref.py` has three classes: `ToGoldenTests` and `CorrelateTests` always run (round trip of the eight goldens through a raw dump built from them, a hand-made raw sample in OpenSTA's text, perturbed golden copies); only `OpenStaTests` is skipped unless `run.sh --probe` succeeds. Source: PROMPT_P5.md R39 ("tested on a hand-made sample output"). Later: none.
- 2026-11-05 · R39 · Pins with direction `internal` (the `ff (IQ, IQN)` nodes OpenSTA makes pins) are left out of the dump; the launching CK pin of a register path is taken from the path's pin chain (`[$path pins]`), since `points` start at Q, and written with edge rise (the edge is not exposed in Tcl; all `toy2.lib` flops are `rising_edge`); the clock port before it is left out. Source: first ff2_default run. Later: a library with falling-edge flops needs the edge from the clock path.
- 2026-11-05 · R39 · The adapter writes OpenSTA's numbers as they come, including the CK-pin conventions under an ideal clock (graph slew 0, arrival without latency, fall arrival at T/2); it does not substitute `set_clock_transition` or the latency, because that would be the adapter computing the toy's model. Source: §3 ("OpenSTA is the reference, not the truth"). Later: R40 classifies them.
- 2026-11-05 · R39 · Oracle rule outcome: the eight designs do not correlate within 1 ps on every column (all eight FAIL, mostly on the CK conventions above), so `s1423` is stored as `tests/snapshot/s1423/` (engine output, with a README saying it is a snapshot) with a byte-exact test in `tests/test_ref.py` (`S1423SnapshotTests`), not as `tests/golden/s1423/`. Source: PROMPT_P5.md R39 oracle rule. Later: if R40 finds the differences are all reporting conventions, the lead may revisit.
- 2026-11-05 · R39 · Logic level for the `--design` grouping: level 0 = PI, clock port or CK pin; an input pin or output port has its net driver's level; an output pin is 1 + the max level of the related pins of its own `timing ()` groups. `correlate.py` reads Verilog and Liberty with its own ~80 lines of regex readers so it does not import `sta_toy` (it judges the engine). Source: PROMPT_P5.md R39. Later: none.

## Correlation summaries (R40 input)

First reading, not a classification (that is R40's):

- Every path node sequence matches on the eight P2 designs (55 of 55). On s1423, 134 of 158 match; the 24 that differ all have the same slack on both sides (max |d| 0.0001, the 6-digit -> fmt4 rounding), i.e. equal-delay alternatives where the toy's tie rule (§6, by pin name) and OpenSTA pick differently.
- s1423 data values agree within 0.0001 on every AT / RAT / slack column (2099 pins, 79 endpoints); its only over-tolerance cells are the 74 CK pins' slew (OpenSTA 0, toy 0.05), plus 75 one-sided NA per fall column (clock port + 74 CK pins: OpenSTA has a fall arrival at T/2) and the clock port.
- ff2_default, ff2_setupviol, ff2_holdviol, inv2: only the CK-pin / clock-port conventions (slew, f arrivals, NA) differ; all endpoint values and paths match.
- ff2_swap, ff2_skew (pin latency): OpenSTA's CK pin arrival excludes the ideal latency (the toy's includes it); in ff2_swap the latency also enters PO required times (+0.3) and, per the x row, input-delay arrivals (+0.3).
- ff2_unc: OpenSTA applies clock uncertainty to the output-port checks (setup RAT -0.5, hold RAT +0.3); the toy does not (§7).
- s27: input-delay arrivals include the 0.2 clock latency; `G3` (only `-max 2.0`) gets 2.0 as its min arrival too (the toy: 0), which moves the early values downstream by up to 2.5.
