# P5 W1 (viewer) notes: R32, R33, R34

Branch `p5-viewer` from `p5-ref` @ bbb685d. Contract: `docs/contracts/viewer_p4.md`
"Changes in P5 (2026-11-05)", written and committed before the code.

## Decisions I made

1. **Font scale is `s / s_default`, not `s`** (R32). Tk font sizes are points, and Tk
   already scales points by the display (`tk scaling`). The brief's non-aqua default
   `s = tk scaling * 72 / 96` would double the fonts on a high-DPI X11 screen if fonts were
   also multiplied by `s`. So `font(kind, size)` uses `size * s / s0`. On aqua `s0 = 1`, so
   fonts are exactly `size * s`, as the brief says. Pixel constants use `px(v) = v * s`.
2. **Window minimum vs. screen** (R32). `minsize` comes from the pane minimums at `s`
   (1066x414 at `s = 1`). When it is larger than `min(1520 s, 92 % screen)`, which can
   happen with a large `--scale` on a small screen (1333 px wide at 1.25), the window opens
   at the minimum, placed at x = 0. Panes are never squeezed below the size where their
   columns fit. At `s = 1` on 1280x800 the window is 1177x720, so it fits.
3. **Hairlines stay 1 px** (R32). Lines drawn with Tk's default width 1 are not scaled.
   Every explicit width (1.2, 1.3, 1.4, 1.6 ...), arrow shapes and the schematic strokes
   are scaled. Dash patterns are unchanged.
4. **Pure size arithmetic is in `sta_toy/viewer/sizing.py`** (no Tk), so the scale and
   window size can be tested under `/usr/bin/python3` too. The pane minimums moved there
   from `app.py`.
5. **Overlap / cut-off test** (R32). The P4 test only checked overlaps, on `s27`. It now
   covers the eight designs at s in {0.8, 1.0, 1.25} x widths {1100, 1280, 1520}, and adds a
   cut-off check: every text must lie inside its canvas, or inside the scroll region of a
   scrolling canvas. The test maps the window, because a withdrawn window has 1x1 canvases.
   A width below the minimum is clamped to the minimum by Tk, and the test asserts that.
   Stages are stepped once, in the schematic view: a stage changes only the schematic, the
   table and the inspector, and those are the same in both views. The test takes about
   3 minutes under python3.12. Most of that time goes to rendering the mapped window.
6. **Layout fixes the new checks found** (R32). Mono glyphs do not shrink linearly at small
   sizes (Menlo 8 pt is 7 px per character), so measure-based layout replaced fixed
   offsets in three places:
   - In the merge card, the margin `Δ` moves under the expression when both do not fit on one line.
   - The table's scroll region is sized from the measured footnote.
   - The waveform's slack-arrow lanes are 46 px apart (was 34). Before, at the minimum
     centre width, a hold `req` label collided with the setup slack label.
7. **Edge labels carry an anchor** (R33). The brief's shape is `labels = [(t, text)]`. I
   used `(t, text, anchor)` instead. A label sits right of its edge (`w`), or left of it
   (`e`) when the right side would cross a mark line or an earlier label. If both sides
   would, it is dropped. Without the anchor, the 3.5 label on `ff2_holdviol` would be
   dropped, because the hold mark line at 3.6 runs through it. The brief expects both
   3.5000 and 13.5000.
   - `model.waveform` gets optional `text_width` (px) and `axis_px`, to convert label widths
     to time units. With no widths, labels have width 0.
   - Mark lines are checked only on the capture row, because that is the only row they
     are drawn through.
8. **The "8.5000 at the 3.5 edge" bug was not present** (R33). The P4 code labelled only
   rising edges. Computed and drawn labels on `ff2_holdviol` `FF2/D` were 3.5000 and
   13.5000 in both checks. Nothing to fix. The label did run through the hold mark line,
   which is now avoided (decision 7).
9. **Largest incr** (R33). Only Data path rows of kind `cell` / `ckq` take part: the start
   row and the net rows are not cell delays. Ties are within 1e-9. The model marks the rows
   with `largest`.
10. **Near-critical heading** (R33). The threshold is on its own line under the merge
    heading: `near-critical: margin < 0.1000`. On the heading line itself it overlapped the
    title at the 320 px minimum inspector width.
11. **Key 3** (R33) has no binding at all. `root.bind("<Key-3>") == ""` is tested.
12. **`source.note` removed** with the compatibility path (R33). It existed only for it.
13. **The R34 test example in the brief is wrong for `s27` `U14/Y`.** U14 is driven by G0,
    which has `set_input_transition 0.05`, inside the slew grid [0.01, 0.2]. So U14/Y has
    no extrapolation. The slew-0 cases are:
    - the CK pins (no `set_clock_transition`): `FF7/Q` in the `FF7/D` setup path, and every
      `t_setup` / `t_hold` on its `related_pin_transition` axis;
    - G2 (no `set_input_transition`): `U13/Y` in the `FF7/D` hold path.

    The test asserts `extrapolated below` on the slew axis for those, and asserts that
    `U14/Y` has none.
14. **Lookup grid in engine mode only** (R34). A bundle holds delays, not tables, so
    `BundleSource.arc_lookup` / `check_lookup` return `None` and no grid is drawn. Of
    several arcs between the same two pins, the grid shows the one whose delay gives the
    arrival (R21's rule). Its `value` is tested equal to the path's `incr`.
15. **Fanout in bundle mode** (R34). A bundle's edges stop at the cone, so counting them
    would undercount. `BundleSource.pin()["fanout"]` reads an optional node field
    `fanout`, which bundle.py does not write yet (see "Requests"). Until it does, the
    fanout column is empty in bundle mode. In engine mode, fanout is `None` exactly when
    `load` is `None` (the pin drives no net), which covers input pins and the capture pin.
16. **s1423 smoke test** skips when `data/s1423.v` or `data/sdc/s1423.sdc` is missing. I
    ran it locally against a temporary, uncommitted copy of W3's files (since deleted). It
    took 1.0 s, against the 10 s bound: open plus engine load, worst setup endpoint, both
    views, three steps, Hold, `[`, `]`.
17. **Screenshots: not possible here.** `screencapture -x -R...` exits 0 but captures only
    the desktop wallpaper, because this process has no Screen Recording permission.
    Stopped after one try, as the brief requires. No PNGs.

## README paragraph (viewer)

`python -m sta_toy.viewer ... [--scale S]` sets the UI scale (0.6 to 2.0). The default is
1.0 on macOS, and elsewhere comes from the display's DPI. The window opens at most 92 % x
90 % of the screen and is centred, so it fits on a 1280x800 laptop. The Profile view is
gone: keys `1` and `2` switch between schematic and waveform, and the path table shows the
largest cell delay in bold. In engine mode, the inspector shows the table lookup grid behind
each delay, output slew and setup / hold time, and marks queries outside the table as
`extrapolated below` / `above`. The path table and the inspector also show each driving
pin's fanout.
