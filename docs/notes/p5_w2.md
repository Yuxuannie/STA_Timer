# P5 notes — W2 (engine, branch `p5-engine`)

## Decisions I made

- R35 · "D pins whose capture CK pin has no arrival (register not on the clock net)":
  the engine gives every CK pin the ideal clock arrival (`p2_semantics.md` §5), so no
  CK pin ever lacks an arrival. Read as the parenthesis says: a CK pin is *clocked*
  when it is a load of the clock port's net (`TimingGraph.clocked`, filled in `build`).
  An unclocked register is still timed with the ideal clock (N30: no semantic change);
  `--check-timing` is where it shows.
- R35 · Ignored-arc row key: `(cell, pin, related_pin, type)`; `type` is the
  `timing_type`, or `combinational:<sense>` (`combinational:none` when missing) when
  the sense is the reason. The row count is the number of arcs ignored for that key
  (instances × groups with that key, = instances in practice). The section count and
  the warning `<n>` are the sum of the rows.
- R35 · Table checks (missing table, not 2-D) run only for supported groups; an ignored
  group's tables are never read, so a `recovery_rising` group with a 1-D or scalar
  table cannot fail the run.
- R35 · Lookup count `m` covers forward, check and backward only (not paths, reports,
  bundles, viewer). Backward now looks up only the delay table (it used to call
  `arc_delay`, which also looked up the transition and threw it away): the same
  floats, one lookup fewer, so `m` counts real work. "Count once per lookup call":
  forward does two calls per cell-arc candidate (delay, transition).
- R35 · `query` / `grid` ranges of section 7: the range of the out-of-grid query values
  on that axis, and the union of the grid ranges of the tables those lookups used.
- R35 · Section counts are always printed, even 0; sections are never omitted.
- R35 · The warning goes to stderr after stdout is flushed and after every file is
  written; an error later in the run prints only the error line.
- R35 · The `--sdc needs an output option` message lists the two new options:
  `(--dump-tsv, --report-timing, --report-summary, --json, --bundle, --check-timing or
  --trace)`. The existing test matches only the prefix, so it is unchanged.
- R35 · s27's golden says `unconstrained endpoints: 0`: `G17` has `-max` only, so its
  hold check is NA, but it is constrained (an endpoint) — the section follows the
  brief (output ports without `set_output_delay`), not "endpoints with an NA check".
- R36 · Log keys beyond the brief, all engine values: forward entries carry `at` (the
  AT set) and `source` (`"input"` / `"clock"` for the §5 sources, which
  `set_sources(log)` now logs so every candidate's source has a block of its own);
  check entries carry `rf`, `ck` and `output_delay` (a PO check is logged per facet
  and rf with the D-only keys `None`); path entries carry `pin` and `rf`. Without
  `rf` a check entry would be ambiguous (r and f are separate lookups).
- R36 · Backward `winner` is the first candidate equal to the min / max — exactly what
  Python's `min()` / `max()` return, so no new tie rule.
- R36 · "both modes printed, late before early": per pin, in engine order (late r,
  late f, early r, early f), not one whole late section then one early section; the
  engine loop is per node, then per mode.
- R36 · Slack and path sections hold only the endpoint (its four slacks, then the
  setup and hold worst paths); cone-internal slacks have no golden to cross-check and
  the engine never computes them during a run.
- R36 · The header's `<sdc>` is the SDC file's base name, so the golden does not
  depend on the working directory; `<design>` is the netlist module name.
- R36 · The cone is `bundle._cone(e, float("inf"))` itself (imported, not copied), so
  the two definitions cannot drift. It is a private name of `bundle.py` (not mine);
  see "Needs in other files".
- R36 · The trace's "not an endpoint" check runs after report_timing, summary and
  check_timing are formatted and before any file is written; `--trace` with a
  non-endpoint writes nothing and prints only the error line.
- R37 · Lead's precondition checked first: `data/toy.lib` and `data/toy2.lib` both
  declare `time_unit : "1ns"` and `capacitive_load_unit (1, pf)`, so the new error
  cannot turn a golden run into an error; the error part is implemented.
- R37 · The units check is in `design.load` (the CLI and viewer load path), right after
  each library is parsed and built, not inside `liberty.loads`: the parser unit tests
  build libraries without `time_unit` (e.g. `test_table_index_overrides_template`,
  `test_graph.MERGE_LIB`) and must pass unchanged. Order: library 1 parse/build, its
  units, library 2 parse/build, its units, ... ("ordered with the other library
  errors"). The builder no longer reports a *missing* `capacitive_load_unit` (it
  reported `capacitive_load_unit must be (<value>, <unit>)` at the library line; no
  test asserted it); a malformed one keeps that error.
- R37 · Error class: `P2Error(file, None, ...)` so the line is exactly
  `<file>: library <name>: missing time_unit` (no `ERROR ` prefix, no line number), as
  the brief writes it. Also `unknown time_unit <value>` / `unknown
  capacitive_load_unit <unit>` for a unit outside fs..s / fF..F (any case).
- R37 · Factors are exact `Fraction`s (powers of ten times the unit's number) and are
  applied as `x * num / den`, so ps -> ns divides by 1000 instead of multiplying by
  0.001.
- R37 · Converted: table values of all six kinds (all are times), axes by their
  template variable suffix (`_transition` time, `_capacitance` cap), pin
  `capacitance` / `rise_capacitance` / `fall_capacitance`. "`set_load`-compatible
  values": the toy reads no other capacitance attribute (no `max_capacitance`), so
  pin capacitances are all there is; SDC `set_load` is in the main library's units.
  Template index lists are shared between tables, so conversion rebinds new lists
  (tested: two tables on one template are each scaled once).
- R37 · `gen_toy2_lib.py --time ps --cap ff --suffix _P` also renames the library to
  `toy2_P`; with no options the output is still `data/toy2.lib` byte for byte
  (tested).

## README paragraphs (for the lead to move)

**check_timing.** `--check-timing` (with `--sdc`) prints what the run left
unconstrained or could not time: outputs without `set_output_delay`, registers whose CK
pin is not on the clock net, inputs without `set_input_delay` / `set_input_transition`,
outputs without `set_load`, the `timing()` groups the timer ignored, and how many table
lookups fell outside their grid (per table kind and axis). A run that ignored any
`timing()` group (recovery, removal, min_pulse_width, falling_edge, ...) still succeeds
and prints one warning line on stderr.

**Library units.** Every library must declare `time_unit` and
`capacitive_load_unit`. The first `--lib` sets the units of the run (SDC values and
every output); a further library in other units (say ps / fF) is converted to them
when loaded. `python3 tools/gen_toy2_lib.py --time ps --cap ff --suffix _P` writes a
ps / fF copy of toy2.lib with suffixed cell names to try it.

**trace.** `--trace PIN` prints, for one endpoint, the engine's own log of how its
values were obtained: every forward merge in its fan-in cone with each candidate
(`AT + delay = value`, the winner marked `*`), the check (constraint, clock arrival,
period, uncertainty), every backward merge, the endpoint's slacks and its worst setup
and hold paths. The numbers are the engine's, logged as it computed them.
