# P5 notes — W2 (engine, branch `p5-engine`)

## Decisions I made

- R35 · "D pins whose capture CK pin has no arrival (register not on the clock net)":
  the engine gives every CK pin the ideal clock arrival (`p2_semantics.md` §5), so no
  CK pin ever lacks an arrival. Read as the parenthesis says: a CK pin is *clocked*
  when it is a load of the clock port's net (`TimingGraph.clocked`, filled in `build`).
  An unclocked register is still timed with the ideal clock (N30: no semantic change);
  `--check-timing` is where it shows.
- R35 · Ignored-arc row key: `(cell, pin, related_pin, type)`; `type` is the
  `timing_type`, or `combinational:<sense>` (`combinational:none` when missing) when
  the sense is the reason. The row count is the number of arcs ignored for that key
  (instances × groups with that key, = instances in practice). The section count and
  the warning `<n>` are the sum of the rows.
- R35 · Table checks (missing table, not 2-D) run only for supported groups; an ignored
  group's tables are never read, so a `recovery_rising` group with a 1-D or scalar
  table cannot fail the run.
- R35 · Lookup count `m` covers forward, check and backward only (not paths, reports,
  bundles, viewer). Backward now looks up only the delay table (it used to call
  `arc_delay`, which also looked up the transition and threw it away): the same
  floats, one lookup fewer, so `m` counts real work. "Count once per lookup call":
  forward does two calls per cell-arc candidate (delay, transition).
- R35 · `query` / `grid` ranges of section 7: the range of the out-of-grid query values
  on that axis, and the union of the grid ranges of the tables those lookups used.
- R35 · Section counts are always printed, even 0; sections are never omitted.
- R35 · The warning goes to stderr after stdout is flushed and after every file is
  written; an error later in the run prints only the error line.
- R35 · The `--sdc needs an output option` message lists the two new options:
  `(--dump-tsv, --report-timing, --report-summary, --json, --bundle, --check-timing or
  --trace)`. The existing test matches only the prefix, so it is unchanged.
- R35 · s27's golden says `unconstrained endpoints: 0`: `G17` has `-max` only, so its
  hold check is NA, but it is constrained (an endpoint) — the section follows the
  brief (output ports without `set_output_delay`), not "endpoints with an NA check".

## README paragraphs (for the lead to move)

**check_timing.** `--check-timing` (with `--sdc`) prints what the run left
unconstrained or could not time: outputs without `set_output_delay`, registers whose CK
pin is not on the clock net, inputs without `set_input_delay` / `set_input_transition`,
outputs without `set_load`, the `timing()` groups the timer ignored, and how many table
lookups fell outside their grid (per table kind and axis). A run that ignored any
`timing()` group (recovery, removal, min_pulse_width, falling_edge, ...) still succeeds
and prints one warning line on stderr.
