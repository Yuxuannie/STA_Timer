# Decisions

## Assumptions

- All input errors raise one exception class, `sta_toy.StaError`, with `file`, `line` (or `None`) and `message` attributes; each module re-exports it and tests check those attributes.
- Entry points the tests rely on: `liberty.parse`/`parse_file` (R1 tree), `liberty.load`/`loads` (R2 library), `verilog.parse`/`load`, `graph.Graph`, `graph.link`.
- R4 has its own test (`test_graph_structure`) that builds a graph by hand, so the data structure can be checked before the linker exists.
- `liberate_dbx2.pdf`, present in the folder before the run and not part of the spec, is left untracked.
- Liberty numbers and identifiers are one token kind ("word": any run of characters other than whitespace, `(){}:;,"\`, or the start of a comment), stored as strings; the accessors convert numbers.
- Attribute values and group names are stored as strings with quotes removed; the tree does not record whether an attribute was written simple or complex.
- A Liberty file holds exactly one top-level group; anything after it is a parse error.
- A Liberty parse error at end of file inside a group is reported as that innermost group being unclosed, at its header line.
- A newline inside a quoted Liberty string without a `\` continuation is kept as part of the string.
- When a Liberty attribute is repeated where one value is expected (`direction`, `capacitance`, `timing_sense`, ...), the first occurrence is used.
- Two `cell` groups with the same name: the later one replaces the earlier in `Library.cells`.
- `pin (A, B)` defines one signal pin per listed name, sharing the group's attributes; a `pin` group with no name is an error.
- A `pin` without `direction` is an error at the pin group's line.
- A `related_pin` that is not a signal pin of the same cell is an error at the `related_pin` line (the linker could not build the arc otherwise).
- A `timing ()` group without `related_pin` defines no arcs.
- A missing `capacitive_load_unit`, or one without exactly two values, is an error at the library line (the graph header needs it).
- A timing group with two NLDM tables of the same header keeps the later one; `Timing.tables` is keyed by header.
- The unknown-template check runs for every NLDM table, even one that gives both indices itself; templates come from `lu_table_template` only (plus the predefined `scalar`).
- Absent indices are returned as `[]`: 1-D tables have `index_2 == []`, `scalar` tables have both empty and `values == [[v]]`.
- An NLDM table with `index_2` but no `index_1` (own or from the template) is a shape error.
- A Verilog net must be declared (as a port or wire) before the connection that uses it; the error is reported at the net name.
- Verilog redeclarations other than `output` + `wire` are errors (`input` twice, `input` + `wire`, `input` + `output`, ...), as are `input`/`output` names missing from the module port list, duplicate instance names, a pin connected twice in one instance, and an instance with an empty connection list.
- Verilog keywords (`module`, `endmodule`, `input`, `output`, `wire`) cannot be used as names.
- An error at end of file (Liberty or Verilog, outside an open Liberty group) reports the line where the file ends.
- Link-time driver checks run over nets in declaration order, so the first bad net in the netlist is reported; for a net declared both `output` and `wire`, the reported line is its first declaration.
- An input port with no loads, or an instance output pin left unconnected, is not an error; such nodes simply have no net edges.
- The CLI accepts `--lib` and `--verilog` in either order, each exactly once with a value; anything else prints the usage error.
- Input files are read as UTF-8; a file that cannot be opened or decoded is reported as unreadable (`ERROR <file>: cannot read file: ...`).
- Stdout is written as UTF-8 bytes so line endings stay `\n` on every platform.
- TRACE.md splits `file[:function]` into separate file and function columns, so `-` can mark the function of a data file as section 7 describes.

- 2026-11-04 · R10 · `rise_constraint` / `fall_constraint` join the four delay/transition kinds in `Timing.tables`, so the stage 1 load-time checks (template exists, shape) cover them too. `Table.variables` holds the template's `variable_1`/`variable_2` (`()` for `scalar`); a table's own `index_1`/`index_2` still override the template's. Source: PROMPT_P2.md R10, p2_semantics.md §4. Later: none.
- 2026-11-04 · R10 · A pin is a clock pin only when `clock : true` is written; any other value or no attribute means not a clock pin. Source: p2_semantics.md §1. Later: re-check against real libraries in stage 3.
- 2026-11-04 · R11 · Linear extrapolation: outside the grid the end segment is extended linearly on each axis; nothing is clamped. At a grid point shared by two segments the lower segment is used (both give the same value). Source: p2_semantics.md §4. Later: stage 2 compares extrapolated values with OpenSTA / PrimeTime, which may clamp or use other end-segment rules.
- 2026-11-04 · R12 · Clock net not traversed: the clock port's net gets no edges, so CK pins have no fan-in and the clock port no fan-out; CK pins are sources (§5), defined for `r` only. Every load of the clock net must be a CK pin, else `clock port X drives a non-clock pin Y`, reported at the netlist line of that `.PIN(` (or of the output port's declaration). Source: p2_semantics.md §2, §5. Later: stage 3 (propagated clocks) puts the clock network back into the graph.
- 2026-11-04 · R12 · The timing graph is built from the netlist and library; it reuses only the stage 1 net edges (driver → loads) and none of the stage 1 cell edges. The stage 1 graph and ASCII writer are untouched. Source: p2_semantics.md §3. Later: none.
- 2026-11-04 · R12 · Unsupported `timing_type`, a combinational arc whose `timing_sense` is missing or not positive/negative/non_unate, a missing table, or a table that is not 2-D over the expected variables are errors at the Liberty line of the `timing ()` group. They are checked only for cells the netlist instantiates; loading the library stays permissive (N15). `timing_sense` is not read for `rising_edge` arcs. Source: p2_semantics.md §3, §10. Later: stage 3 adds the falling and asynchronous arc types.
- 2026-11-04 · R13 · Unset SDC facets are 0 and pin-level latency wins: the parser stores `-min`/`-max` and `-setup`/`-hold` facets separately, a later line replaces only the facets it names (plain = both), and an input-delay facet never set reads as 0. `set_clock_latency` on `[get_pins ...]` is kept apart from the clock-level value and always wins for that pin; repeated pin or clock lines: the later one wins. Output-delay facets are kept only when set (see R16). Source: sdc_subset.md "Facets and overriding", p2_semantics.md §5. Later: stage 2 confirms these defaults against OpenSTA / PrimeTime.
- 2026-11-04 · R13 · SDC syntax details the contract leaves open: a `;` or any other token after the object list is an extra token (error); an object list that is not one of the command's kinds counts as malformed; a word where an option or value is expected is an "unexpected token" error; the `-name`/`-clock` argument is any token that is not an option; `-period` must be a number. Source: sdc_subset.md "Lexical rules". Later: none.
- 2026-11-04 · R13 · Semantic SDC checks run in this order: "no create_clock" first (reported at the file's last line), then every object the file names, in file order (an object list before the `-clock` of the same line). A clock named before `create_clock` is a syntactic error; once a clock exists, a different clock name is a semantic one. Source: sdc_subset.md "Errors", "Order". Later: none.
- 2026-11-04 · R14 · Ideal clock: every CK pin is a source with `AT = L` in both modes and `SLEW = set_clock_transition` (default 0), defined for `r` only; its `f` values and all values of the clock port stay NA. `L` is the pin-level `set_clock_latency` if given, else the clock-level value, else 0. Source: p2_semantics.md §5. Later: stage 2 checks the CK-pin slew source against OpenSTA under an ideal clock; stage 3 replaces this with propagated clocks.
- 2026-11-04 · R15 · Worst-slew policy: a node's SLEW is the max (late) / min (early) of the candidate slews of every incoming arc pair with a defined source AT, independent of which candidate sets the AT. Source: p2_semantics.md §6. Later: stage 2 re-checks the policy against a reference tool (OpenSTA / PrimeTime may take the slew of the AT-setting arc).
- 2026-11-04 · R15 · Forward tie rule: candidates are sorted by (source node name, `r` before `f`) with plain string order, and a later candidate replaces the current best only when it is better by more than 1e-9. Ties therefore go to the first candidate, ordered by the pin name (`U1/A` before `U1/B`), not by the port name upstream. Source: p2_semantics.md §6, §11. Later: none.
- 2026-11-04 · R15 · A combinational loop is reported as `error: combinational loop: A -> B -> ... -> A`, with no file position, because a loop has no single line. Source: p2_semantics.md §6, cli_p2.md. Later: none.
- 2026-11-04 · R16 · Unconstrained output ports are not endpoints, and a missing facet leaves NA: an output port is an endpoint only if `set_output_delay` set at least one facet; `RAT[late]` needs the `-max` facet and `RAT[early]` the `-min` facet, otherwise it stays NA (as do the backward RATs that depend only on it). Every D pin (input pin owning a `setup_rising`/`hold_rising` group) is an endpoint, even when its RATs are NA. Clock latency and uncertainty never enter a PO required time. Source: p2_semantics.md §7. Later: P3 reports must show NA checks the same way.
- 2026-11-04 · R16 · Setup uses `AT[late]` and `SLEW[late]` of the capture CK pin and late D slews; hold uses the early ones. If a D pin had two groups of the same check kind, the later group's RAT would replace the earlier one (toy2.lib has one of each). Source: p2_semantics.md §7. Later: none.
- 2026-11-04 · R17 · Backward runs in reverse topological order, skips endpoints (their RAT comes only from §7), and needs the node's own slew in that mode to compute a candidate; no candidate leaves NA. Source: p2_semantics.md §8. Later: none.
- 2026-11-04 · R18 · Endpoint transition tie rule: the reported transition `rf*` of a check is the one with the smaller slack; `f` wins only when its slack is smaller by more than 1e-9, so ties go to `r`; if only one transition has a slack, that one is used; if neither, the three cells are `NA` and no path line is written. Source: p2_semantics.md §9, golden_format.md. Later: P3 reports use the same `rf*`.
- 2026-11-04 · R18 · The `fmt4` rule is applied only when writing the three files (`round(v, 9)`, then `Decimal` `ROUND_HALF_UP` to 4 places, `-0.0000` written as `0.0000`); every computation keeps full floats. Source: p2_semantics.md §11. Later: stage 2 compares with `--tol` 1 ps instead of byte equality.
- 2026-11-04 · R18 · Error order: arguments, then each `--lib`, the netlist, the stage 1 link (unknown cell, unknown pin, zero or several drivers), SDC syntax, SDC semantics, then the timing graph (clock port driving a non-clock pin, unsupported `timing_type`/`timing_sense` or table, combinational loop), then writing the files. The first error stops the run. Source: p2_semantics.md §10. Later: none.
- 2026-11-04 · R18 · Error line format, chosen by the user when asked: errors stage 1 already reports (Liberty, Verilog, link, unreadable file) keep `ERROR <file>:<line>: ...` byte for byte; new P2 errors print `<file>:<line>: ...`, or `error: ...` without a position; argument errors, including a missing `--lib`/`--verilog`, are `error: ...` with no usage text. This replaces the stage 1 usage-line entry above. Source: cli_p2.md. Later: none.
- 2026-11-04 · R18 · `--lib` may repeat: cells are looked up in command-line order, first definition wins; the library name and units of the stage 1 header come from the first library; no unit conversion. Any argument that is not one of the four options is reported as an unknown option, a missing option value or a repeated `--verilog`/`--sdc`/`--dump-tsv` is an error, and `--dump-tsv` creates the directory if needed (a failure to write is `error: cannot write ...`). Source: cli_p2.md. Later: stage 3 defines multi-library link order properly.

- 2026-11-04 · R21 · The engine nodes now carry their cell name, arcs their kind (`net` / `cell` / `ckq`), the graph its SDC, and the library its `time_unit`; `design.py` holds the load-and-time chain shared by the CLI and the viewer. No P2 value changes. Source: SPEC_P3P4.md. Later: none.
- 2026-11-04 · R21 · When PRED points to a node with two timing() arcs to the same pin and pair, the worst path uses the arc whose delay gives the AT (largest late, smallest early). Source: report_p3.md §2. Later: none.
- 2026-11-04 · R22 · Path order is `round(slack, 9)` then the path key read from the endpoint backwards; this reproduces the P2 tie rules, so the first enumerated path is always the `paths.txt` path (tested on all eight designs). K-worst paths come from a best-first search whose bound is exact. Source: report_p3.md §1-§2. Later: P3 report options beyond these (`-unique_pins`, path groups) are not built.
- 2026-11-04 · R24 · WNS is the worst slack even when positive; TNS sums negative slacks only; NVP counts slacks below −1e-9. Source: report_p3.md §5. Later: check against OpenSTA's `report_wns` / `report_tns` conventions in stage 2.
- 2026-11-04 · R23 · The report block is formatted from the json_v1 path object alone: a PI start is recognised by `launch.input_delay`, a flip-flop endpoint by `capture.pin`; a port point prints `(in)` as the first point and `(out)` otherwise; capture rows are sums of the rounded object values, and `-0.0` prints `0.0000` through fmt4. Source: report_p3.md §4. Later: P3 report options beyond these (`-input_pins` off, `-nets`) are not built.
- 2026-11-04 · R25 · JSON: `pin_latency` keys are sorted by pin; an endpoint check without a slack is `{rf, at, rat, slack}` all null; `dumps` is `json.dumps(obj, indent=2)` with its defaults plus `\n`; write errors are `error: cannot write <path>: <reason>`. Source: json_v1.md. Later: schema v1 is frozen; changes need v2.
