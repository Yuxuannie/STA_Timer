# Stage P2 — Sequential timing engine (setup / hold, forward / backward)

## 0. Purpose and who judges

This repository already contains stage 1: a Liberty parser (R1/R2), a Verilog
parser (R3), a linker (R4), a pin-level graph (R5) and an ASCII writer (R6),
with tests and docs. Read `README.md`, `TRACE.md` and `DECISIONS.md` first and
keep every stage 1 behavior and test intact.

Stage P2 turns that graph into a timer: for a flat netlist with D flip-flops
and combinational cells, under one ideal clock described by a small SDC file,
compute arrival time, required time and slack for every pin, early and late,
rise and fall, and the worst path of every endpoint.

A reviewer will read this prompt and the resulting repo side by side. They
check two things: every requirement below can be traced to code and a test,
and nothing beyond those requirements was built. Correctness is decided by
golden files produced by an independent oracle (section 5), not by your own
judgment. If you believe a golden value is wrong, stop and report the
smallest case that shows it; do not change the oracle or the golden.

The contract files under `docs/contracts/` are part of this prompt. When
this prompt and a contract disagree, the contract wins; when a contract is
ambiguous, stop and ask.

## 3. Rules

The rules live in `docs/contracts/p2_semantics.md` (what is computed),
`docs/contracts/sdc_subset.md` (constraints), `docs/contracts/golden_format.md`
(outputs) and `docs/contracts/cli_p2.md` (invocation). Implement them as
written. Specific points that are easy to get wrong:

- Table axes come from the template's `variable_1` / `variable_2` names.
  `del_3x3` has load on axis 1 and slew on axis 2; `cons_3x3` has D slew on
  axis 1 and CK slew on axis 2.
- The delay and transition tables for an arc are chosen by the **output**
  transition (`cell_rise` for the output rising), whatever the input transition.
- Slew is merged with the worst-slew policy, independently of which arc wins
  the arrival. Early slews are the minimum over arcs.
- The clock net is not traversed. CK pins are sources with `AT = latency`,
  `SLEW = clock transition`, defined for `r` only.
- Setup uses late slews and `AT[late]` of the capture CK pin; hold uses early
  slews and `AT[early]` of the capture CK pin.
- Facets: `-min` / `-max` and `-setup` / `-hold` are stored separately; a
  later line replaces only the facet it names; an unset facet is 0; a PO
  with only `-max` has NA hold cells. Pin-level clock latency wins over the
  clock-level value whatever the line order.
- Ties in forward (`|Δ| < 1e-9`) go to the candidate first in `(u.name, rf)`
  order with `r` before `f`; endpoint worst transition ties go to `r`.
- Numbers are written with `fmt4` exactly; no other rounding anywhere in the
  computation.

## 5. Oracle and required tests

All tests run with `python3 -m unittest discover -s tests` from the repo
root and must pass on Python 3.8+.

**Golden tests (R19a).** For each of the eight designs run the CLI with
`--sdc` and `--dump-tsv` into a temporary directory and compare with
`tools/diff_ref.py <golden> <actual>` (exit code 0, `--tol 0`). The test must
fail if any cell or path line differs. Designs:

| golden dir | netlist | sdc |
|---|---|---|
| `ff2_default` | `ff2.v` | `ff2_default.sdc` |
| `ff2_swap` | `ff2.v` | `ff2_swap.sdc` |
| `ff2_setupviol` | `ff2.v` | `ff2_setupviol.sdc` |
| `ff2_holdviol` | `ff2.v` | `ff2_holdviol.sdc` |
| `ff2_skew` | `ff2.v` | `ff2_skew.sdc` |
| `ff2_unc` | `ff2.v` | `ff2_unc.sdc` |
| `inv2` | `inv2.v` | `inv2.sdc` |
| `s27` | `s27.v` | `s27.sdc` |

**Interpolation unit tests (R19b).** Build this table in the test (not from
a file): `index_1 = [1, 2, 4]`, `index_2 = [10, 20, 40]`, `values` rows
`[1, 2, 4]`, `[2, 4, 8]`, `[4, 8, 16]`. Assert, to 1e-9:

| query (x1, x2) | expected | what it proves |
|---|---|---|
| (1, 10) | 1.0 | grid point |
| (1.5, 10) | 1.5 | interpolation along one axis |
| (1.5, 15) | 2.25 | interior bilinear (a plane fit would give a different value) |
| (3, 30) | 9.0 | second cell |
| (2, 40) | 8.0 | grid point on the far edge |
| (0.5, 10) | 0.5 | extrapolation below axis 1 |
| (4, 5) | 2.0 | extrapolation below axis 2 |
| (5, 50) | 25.0 | extrapolation beyond both axes; clamping would give 16.0 |

**Template order unit test (R19c).** Using `data/toy2.lib`: `BUF` `cell_rise`
at `input_net_transition = 0.01`, `total_output_net_capacitance = 0.016`
equals 2.12 (swapped axes would give 1.832); the `DFF` **hold**
`rise_constraint` at `constrained_pin_transition = 0.2`,
`related_pin_transition = 0.01` equals 0.17 (swapped axes would give 0.36).

**SDC tests (R19d).** Parser module: one valid file covering every command
form in `sdc_subset.md` including a negative value and the facet/override
rules; one test per **syntactic** error class asserting the message carries
the file name and line number. Through the CLI: one test per **semantic**
error class (`sdc_subset.md` "Errors"), asserting exit code 1 and exactly one
stderr line. The oracle does not check errors; these expectations come from
the contract only.

**Error contract tests (R19e).** Through the CLI, each with exit code 1 and
one stderr line: two drivers on a net (keep the stage 1 message); a clock
port driving a non-clock pin; a combinational loop in a small netlist written
by the test (valid library and SDC, so that the loop is the first error per
`p2_semantics.md` §10); a `timing_type` the timer does not support.

**Forward tie test (R19g).** Netlist written by the test on `toy2.lib`:
input ports `p` and `q`, `NAND2 U1 (.A(q), .B(p), .Y(n))`, `DFF FF1 (.CK(clk),
.D(n), .Q(y))`, output `y`; SDC: period 10, `set_input_delay 1.0` and
`set_input_transition 0.05` on both `p` and `q`, `set_clock_transition 0.05`,
`set_output_delay 1.0` on `y`. Both inputs of `U1` tie exactly. Assert the
setup path line of `FF1/D` is exactly
`FF1/D setup 6.7000 : q(f) -> U1/A(f) -> U1/Y(r) -> FF1/D(r)` and the hold
line is `FF1/D hold 2.9000 : q(f) -> U1/A(f) -> U1/Y(r) -> FF1/D(r)` (the
predecessor order is by the **pin** name `U1/A` < `U1/B`, not by the port
name, and the endpoint transition tie goes to `r`).

**CLI tests (R19h).** Unknown option → exit 1, one stderr line, no usage
text; `--sdc` without `--dump-tsv` and `--dump-tsv` without `--sdc` → exit 1;
a successful `--sdc --dump-tsv` run writes nothing to stdout; without `--sdc`
the stage 1 behavior and output are unchanged.

**Stage 1 regression (R19f).** Every stage 1 test still passes and the ASCII
output for `c17` is byte-identical to its golden.

## 6. Process

1. Read `README.md`, `TRACE.md`, `DECISIONS.md`, then the four contracts, then
   this prompt again. List the open questions you have **before** writing
   code; if any question changes a golden number, stop and ask now.
2. Create branch `p2-engine` from the current `HEAD`. Do all work on it.
3. One commit per requirement ID (or a small group of closely related IDs),
   message starting with the ID(s), e.g. `R11: bilinear table lookup`.
   Run the full test suite before every commit; never commit a red suite.
4. Stop and ask when: a Liberty or Verilog construct in the inputs is outside
   what stage 1 parses and the fix is not obvious; a contract is ambiguous;
   a golden value looks wrong; anything in the "do not build" table seems
   necessary; `git push` is rejected or no remote is configured.
5. Never edit the files listed in N22. Never regenerate golden files.
6. When everything in section 8 holds, push the branch:
   `git push -u origin p2-engine`. Do not force-push, do not rebase published
   commits, do not merge into the default branch. If `origin` does not exist,
   stop and ask for the remote URL instead of creating a repository.
7. Finish with a short summary: branch name, final commit hash, test count,
   and the list of DECISIONS entries added.
