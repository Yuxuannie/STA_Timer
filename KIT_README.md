# P2 kit — how to use

Copy everything in this folder into the root of the stage 1 repo (the one
with the Liberty / Verilog parsers and the ASCII graph), commit it on the
default branch as "P2 inputs: contracts, data, oracle, golden", then start
Claude Code in the repo and give it `PROMPT_P2.md`.

```
p2kit/
  PROMPT_P2.md                 the prompt for Claude Code
  docs/contracts/
    p2_semantics.md            what the engine computes (the rules)
    golden_format.md           the three output files and fmt4
    sdc_subset.md              the constraint language
    cli_p2.md                  command line and error contract
  data/
    toy2.lib                   generated by tools/gen_toy2_lib.py; affine tables
    ff2.v  inv2.v  s27.v       netlists
    sdc/*.sdc                  8 scenarios (6 for ff2, inv2, s27)
  tools/
    gen_toy2_lib.py            lib generator (provenance; not used at run time)
    oracle/oracle.py           independent oracle (own parsers, plane fit)
    oracle/make_golden.py      regenerates tests/golden/*  (never edit golden by hand)
    diff_ref.py                golden comparison; the tests call it with --tol 0
  tests/golden/<design>/       endpoints.tsv  pins.tsv  paths.txt
```

Before launching Claude Code, run once from the repo root to confirm the
golden files are reproducible on your machine:

```
python3 tools/oracle/make_golden.py && git status --short tests/golden   # should print nothing
```

What Claude Code is told to do at the end: work on branch `p2-engine`,
one commit per requirement ID, then `git push -u origin p2-engine`.
It will stop and ask if `origin` is missing. It must not touch `data/`,
`tests/golden/`, `tools/oracle/`, `tools/diff_ref.py` or `docs/contracts/`
— check `git diff --stat <default-branch>..p2-engine -- data tests/golden tools/oracle docs/contracts tools/diff_ref.py`
when it is done; it should print nothing.

Numbers to recognise while reviewing:
- `ff2_default`: FF2/D setup slack 5.7000, hold slack 2.9000 (the walkthrough page).
- `ff2_skew`: 6.2000 / 2.4000.  `ff2_holdviol`: hold −0.6000.  `ff2_setupviol`: setup −0.3000.
- `ff2_swap`: setup path now starts at FF1/CK, hold path at x (5.5000 / 3.6000).  `ff2_unc`: 5.2000 / 2.6000.
- `inv2`: U2/Y arrival 2.0000 rise and fall while U1/Y is 1.2000 / 0.8000; y arrival 2.5500 (set_load seen by U3).
- `s27`: U15/Y slew_late_r 0.0560 (worst-slew policy), FF5/D rat_late_f 9.8222 (extrapolation at CK slew 0), G17 hold cells NA.
